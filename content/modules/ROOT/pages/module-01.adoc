= YAML Fundamentals

== Introduction

Welcome to YAML Essentials for Ansible! In this lab, you'll learn the fundamentals of YAML (YAML Ain't Markup Language), a human-readable data serialization language that Ansible uses for all its configurations, playbooks, and tasks.

*YAML (YAML Ain't Markup Language)* is a data serialization standard that makes it easy to read and understand code at a glance. Ansible Automation Platform uses YAML because it offers a straightforward, human-readable way to write configurations, tasks, and playbooks.

In this module, you will:

* Learn basic YAML data types: scalars, lists, and dictionaries
* Understand YAML indentation and structure rules
* Create your first YAML inventory file
* Master case sensitivity in YAML

=== Why YAML for Ansible?

YAML offers several advantages for automation:

* *Readability:* YAML's structure makes it simple for users of all skill levels to understand and write Ansible content
* *Support for complex use cases:* YAML can represent lists and dictionaries, allowing complex configurations with simplicity
* *Wide adoption:* YAML skills are transferable across many configuration management tools
* *Low learning curve:* YAML's easy syntax lowers the barrier to getting started with Ansible

== YAML File Basics

Before we dive into YAML syntax, understand these fundamental rules:

[IMPORTANT]
====
*Critical YAML Rules:*

* YAML files typically use the `.yml` or `.yaml` extension
* YAML is *case-sensitive* - `Name` and `name` are different
* Use *2 spaces* for indentation (never tabs!)
* Files often start with `---` to indicate the beginning of a YAML document
====

.☑️ Task 2 - Add scalars (simple values)
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

YAML has three fundamental data types: scalars, lists, and dictionaries. Let's start with scalars - basic, single-value data types like strings, numbers, and booleans.

. In the left sidebar, click on `inventory.yml` to open it (if it's not already open), then add the following content:
+
[source,yaml]
----
---
web1.example.com
web2.example.com
db1.example.com
----
+
IMPORTANT: Save the file by clicking *File > Save* in the top menu, or press `Ctrl+S` (Windows/Linux) or `Cmd+S` (Mac).

. You should see three hostnames listed in your file. Each hostname is a *scalar* - a simple string value.

TIP: *Strings in YAML:* Quotation marks are optional for most strings in YAML. As a best practice for Ansible, avoid using quotation marks unless necessary (e.g., when a string contains special characters).

.☑️ Task 4 - Use lists (sequences)
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

Lists define collections of items and are identified by leading hyphens (`-`). Ansible uses lists to specify multiple items under a key.

. Update `inventory.yml` in VSCode with list syntax. Replace all the content with:
+
[source,yaml]
----
---
hosts:
  - web1.example.com
  - web2.example.com
  - db1.example.com
----
+
IMPORTANT: Save the file.

. Notice how each hostname now starts with a hyphen (`-`) and is indented with 2 spaces under the `hosts:` key.

.☑️ Task 6 - Create dictionaries (key-value pairs)
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

Dictionaries associate keys with values. They're used throughout Ansible for configurations, variables, and module parameters.

. Update `inventory.yml` in VSCode to use dictionaries and nested structures. Replace all the content with:
+
[source,yaml]
----
---
all:
  vars:
    ansible_connection: local
  children:
    webservers:
      hosts:
        web1.example.com:
        web2.example.com:
    databases:
      hosts:
        db1.example.com:
----
+
IMPORTANT: Save the file.

. This inventory now has:
+
* `all:` - A top-level dictionary key
* `vars:` - Variables that apply to all hosts
* `children:` - A nested dictionary defining groups
* `webservers:` and `databases:` - Group names (dictionary keys)
* `hosts:` - Another nested dictionary containing host lists

NOTE: *Understanding Group Variables:* The `vars:` section under `all:` applies the `ansible_connection: local` setting to all hosts in the inventory. This tells Ansible to run commands on the local machine rather than connecting via SSH.

NOTE: *Understanding Indentation:* Notice the structure uses 2 spaces per level: `all:` is at 0 spaces (top level), `vars:` is at 2 spaces (nested under `all`), `children:` is at 2 spaces (nested under `all`), `webservers:` is at 4 spaces (nested under `children`), and `hosts:` is at 6 spaces (nested under `webservers`). Consistent indentation is critical in YAML!

.☑️ Task 8 - Add host variables (case sensitivity)
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

YAML is case-sensitive, which means `HTTP_PORT` and `http_port` are completely different keys. Let's add some host variables to demonstrate.

. Update `inventory.yml` with the following content:
+
[source,yaml]
----
---
all:
  vars:
    ansible_connection: local
  children:
    webservers:
      hosts:
        web1.example.com:
          http_port: 80
          max_clients: 200
        web2.example.com:
          http_port: 8080
          max_clients: 150
    databases:
      hosts:
        db1.example.com:
          db_port: 5432
----
+
IMPORTANT: Save the file.

WARNING: *Common Mistake - Inconsistent Casing:* If you use `http_port` in one place and `HTTP_PORT` in another, Ansible will treat them as different variables. This is a common source of errors!

== Key Takeaways

In this module, you learned:

* ✅ YAML uses `.yml` extension and often starts with `---`
* ✅ YAML is *case-sensitive* - maintain consistent casing
* ✅ Use *2 spaces* for indentation (never tabs)
* ✅ *Scalars* are simple values (strings, numbers)
* ✅ *Lists* use leading hyphens (`-`) to define sequences
* ✅ *Dictionaries* use `key: value` pairs for structured data
* ✅ Nested structures use consistent indentation
