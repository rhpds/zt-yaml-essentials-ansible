= YAML Fundamentals

== Introduction

Welcome to YAML Essentials for Ansible! In this lab, you'll learn the fundamentals of YAML (YAML Ain't Markup Language), a human-readable data serialization language that Ansible uses for all its configurations, playbooks, and tasks.

*YAML (YAML Ain't Markup Language)* is a data serialization standard that makes it easy to read and understand code at a glance. Ansible Automation Platform uses YAML because it offers a straightforward, human-readable way to write configurations, tasks, and playbooks.

In this module, you will:

* Learn basic YAML data types: scalars, lists, and dictionaries
* Understand YAML indentation and structure rules
* Create your first YAML inventory file
* Master case sensitivity in YAML

=== Why YAML for Ansible?

YAML offers several advantages for automation:

* *Readability:* YAML's structure makes it simple for users of all skill levels to understand and write Ansible content
* *Support for complex use cases:* YAML can represent lists and dictionaries, allowing complex configurations with simplicity
* *Wide adoption:* YAML skills are transferable across many configuration management tools
* *Low learning curve:* YAML's easy syntax lowers the barrier to getting started with Ansible

== YAML File Basics

Before we dive into YAML syntax, let's understand some fundamental rules:

[IMPORTANT]
====
*Critical YAML Rules:*

* YAML files typically use the `.yml` or `.yaml` extension
* YAML is *case-sensitive* - `Name` and `name` are different
* Use *2 spaces* for indentation (never tabs!)
* Files often start with `---` to indicate the beginning of a YAML document
====

== YAML Data Types

YAML has three fundamental data types that you'll use constantly in Ansible:

=== Scalars (Simple Values)

Scalars are basic, single-value data types like strings, numbers, and booleans.

[arabic]
. Let's add some simple host entries to our inventory. In the left sidebar, click on `inventory.yml` to open it (if it's not already open), then add the following content:
+
[source,yaml]
----
---
web1.example.com
web2.example.com
db1.example.com
----
+
Save the file by clicking *File > Save* in the top menu, or press `Ctrl+S` (Windows/Linux) or `Cmd+S` (Mac).

. You should see three hostnames listed in your file. Each hostname is a *scalar* - a simple string value.

. Verify the YAML syntax is valid using VSCode's integrated terminal:
+
* In VSCode, click the *Terminal* menu at the top, then select *New Terminal*
* A terminal panel will open at the bottom of the screen
* In the terminal, run the following command:
+
[source,bash,role=execute]
----
yamllint inventory.yml
----

[TIP]
====
*Strings in YAML:*

Quotation marks are optional for most strings in YAML. As a best practice for Ansible, avoid using quotation marks unless necessary (e.g., when a string contains special characters).
====

=== Lists (Sequences)

Lists define collections of items and are identified by leading hyphens (`-`). Ansible uses lists to specify multiple items under a key.

Let's expand our inventory to use proper list syntax:

[arabic]
. Update `inventory.yml` in VSCode with list syntax. Replace all the content with:
+
[source,yaml]
----
---
hosts:
  - web1.example.com
  - web2.example.com
  - db1.example.com
----
+
Save the file.

. Notice how each hostname now starts with a hyphen (`-`) and is indented with 2 spaces under the `hosts:` key.

. Verify the syntax in the integrated terminal:
+
[source,bash,role=execute]
----
yamllint inventory.yml
----

=== Dictionaries (Key-Value Pairs)

Dictionaries associate keys with values. They're used throughout Ansible for configurations, variables, and module parameters.

Let's create a proper inventory with host groups:

[arabic]
. Update `inventory.yml` in VSCode to use dictionaries and nested structures. Replace all the content with:
+
[source,yaml]
----
---
all:
  vars:
    ansible_connection: local
  children:
    webservers:
      hosts:
        web1.example.com:
        web2.example.com:
    databases:
      hosts:
        db1.example.com:
----
+
Save the file.
+
[NOTE]
====
*Understanding Group Variables:*

The `vars:` section under `all:` applies the `ansible_connection: local` setting to all hosts in the inventory. This tells Ansible to run commands on the local machine rather than connecting via SSH.

Group variables affect all hosts without repeating them individually.
====

. This inventory now has:
+
* `all:` - A top-level dictionary key
* `vars:` - Variables that apply to all hosts
* `children:` - A nested dictionary defining groups
* `webservers:` and `databases:` - Group names (dictionary keys)
* `hosts:` - Another nested dictionary containing host lists

. Verify with Ansible in the integrated terminal:
+
[source,bash,role=execute]
----
ansible-inventory -i inventory.yml --list
----
+
This command shows how Ansible interprets your YAML inventory structure.

[NOTE]
====
*Understanding Indentation:*

Notice the structure uses 2 spaces per level:

* `all:` - 0 spaces (top level)
* `vars:` - 2 spaces (nested under `all`)
* `children:` - 2 spaces (nested under `all`)
* `webservers:` - 4 spaces (nested under `children`)
* `hosts:` - 6 spaces (nested under `webservers`)

Consistent indentation is critical in YAML!
====

== Case Sensitivity in YAML

YAML is case-sensitive, which means `HTTP_PORT` and `http_port` are completely different keys.

Let's add some host variables to demonstrate:

[arabic]
. Add variables to your hosts in VSCode. Update `inventory.yml` with the following content:
+
[source,yaml]
----
---
all:
  vars:
    ansible_connection: local
  children:
    webservers:
      hosts:
        web1.example.com:
          http_port: 80
          max_clients: 200
        web2.example.com:
          http_port: 8080
          max_clients: 150
    databases:
      hosts:
        db1.example.com:
          db_port: 5432
----
+
Save the file.

. Verify the inventory structure in the integrated terminal:
+
[source,bash,role=execute]
----
ansible-inventory -i inventory.yml --list --yaml
----
+
Notice how each host now has variables associated with it. The variable names use consistent casing throughout.

[WARNING]
====
*Common Mistake - Inconsistent Casing:*

If you use `http_port` in one place and `HTTP_PORT` in another, Ansible will treat them as different variables. This is a common source of errors!
====

=== Verify Your Work

Let's create a quick test to ensure your inventory is valid:

[arabic]
. Test that Ansible can read all hosts in the webservers group. In the integrated terminal, run:
+
[source,bash,role=execute]
----

----

. Test the databases group:
+
[source,bash,role=execute]
----

----
