= Your First Playbook

== Introduction

Now that you understand YAML fundamentals, it's time to write your first Ansible playbook! A playbook is a YAML file that defines automation tasks to be executed on your managed hosts.

In this module, you will:

* Learn the structure of an Ansible playbook
* Understand plays, tasks, and modules
* Write a working playbook with multiple tasks
* Execute your playbook against the inventory you created

== Ansible Playbook Structure

An Ansible playbook consists of one or more *plays*. Each play:

* Targets a group of hosts from your inventory
* Contains a list of tasks to execute
* Can set variables and other play-level options

The basic structure looks like this:

[source,yaml]
----
---
- name: Play description
  hosts: target_hosts
  tasks:
    - name: Task description
      module_name:
        parameter: value
----

[IMPORTANT]
====
*Playbook Best Practices:*

* Start playbooks with `---` to indicate the beginning
* Always name your plays and tasks for readability
* Use 2 spaces for indentation consistently
* Use fully-qualified collection names (FQCN) for modules: `ansible.builtin.ping` instead of just `ping`
====

== Hands-On Experience

Let's create a simple playbook that tests connectivity to your hosts and then installs a package.

======
.☑️ Task 1 - Create your first playbook
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

. Create a new file called `site.yml`
. Add the following content:
+
[source,yaml]
----
---
- name: Test connectivity to web servers
  hosts: webservers
  tasks:
    - name: Ping all web servers
      ansible.builtin.ping:
----
+
. Save the file
=====
======

======
.☑️ Task 2 - Validate and run your playbook
[%collapsible]
=====
NOTE: Switch to the *Terminal* tab

. Validate the syntax:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml site.yml
----

. Run the playbook:
+
[source,bash,role=execute]
----
ansible-playbook -i inventory.yml site.yml
----
=====
======

== Adding More Tasks

Let's expand the playbook to install Apache web server on the web servers.

=== Understanding Module Parameters

Ansible modules accept parameters as key-value pairs. The `ansible.builtin.package` module needs to know which package to install:

[source,yaml]
----
ansible.builtin.package:
  name: httpd
  state: present
----

======
.☑️ Task 3 - Add Apache installation tasks
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

. Replace `site.yml` with:
+
[source,yaml]
----
---
- name: Configure web servers
  hosts: webservers
  become: true
  tasks:
    - name: Ping all web servers
      ansible.builtin.ping:

    - name: Install Apache web server
      ansible.builtin.package:
        name: httpd
        state: present

    - name: Start and enable Apache
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true
----
+
. Save the file
=====
======

======
.☑️ Task 4 - Verify and run the updated playbook
[%collapsible]
=====
NOTE: Switch to the *Terminal* tab

. Verify the syntax:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml site.yml
----

. Run the playbook:
+
[source,bash,role=execute]
----
ansible-playbook -i inventory.yml site.yml
----
=====
======

=== Understanding Task Execution

Tasks in a playbook execute in order, top to bottom:

. First task: `ping` - Tests connectivity
. Second task: `package` - Installs httpd
. Third task: `service` - Starts and enables httpd

If any task fails, the playbook stops executing on that host.

=== Boolean Values in YAML

Notice `become: true` in the playbook. YAML supports boolean values:

* Use `true` and `false` (lowercase)
* Ansible also accepts `yes`/`no` for booleans, but `true`/`false` is preferred

[source,yaml]
----
become: true         # ✅ Preferred
become: yes          # ✅ Works, but not preferred
become: True         # ❌ Avoid - case inconsistent
enabled: true        # ✅ Correct
----

=== Module Parameters

Different Ansible modules accept different parameters. Let's look at the parameters we've used:

==== `ansible.builtin.package` Module

[source,yaml]
----
ansible.builtin.package:
  name: httpd          # Package name (string)
  state: present       # Desired state: present, absent, latest
----

==== `ansible.builtin.service` Module

[source,yaml]
----
ansible.builtin.service:
  name: httpd          # Service name (string)
  state: started       # Desired state: started, stopped, restarted
  enabled: true        # Enable on boot (boolean)
----

[TIP]
====
To see all parameters for a module, use:

[source,bash]
----
ansible-doc ansible.builtin.package
----
====

======
.☑️ Task 5 - Verify Apache is running
[%collapsible]
=====
NOTE: Switch to the *Terminal* tab

. Check that Apache is running:
+
[source,bash,role=execute]
----
curl http://localhost
----

== Key Takeaways

In this module, you learned:

* ✅ Playbooks start with `---` and contain plays (lists)
* ✅ Plays have `name`, `hosts`, and `tasks` sections
* ✅ Tasks execute in order from top to bottom
* ✅ Use `become: true` for privilege escalation
* ✅ Module parameters are indented under the module name
* ✅ Use `true`/`false` for boolean values
* ✅ Always use `--syntax-check` to validate YAML
* ✅ Use FQCN (Fully Qualified Collection Names) for modules
