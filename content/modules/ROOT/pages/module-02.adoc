= 2. Your First Playbook

== Introduction

Now that you understand YAML fundamentals, it's time to write your first Ansible playbook! A playbook is a YAML file that defines automation tasks to be executed on your managed hosts.

In this module, you will:

* Learn the structure of an Ansible playbook
* Understand plays, tasks, and modules
* Write and run a simple connectivity test
* Add multiple tasks using different Ansible modules

== Understanding Playbook Structure

Before we start writing, let's understand what we're building. An Ansible playbook consists of one or more *plays*. Think of a play as a set of instructions for a specific group of servers.

Each play has three essential parts:

. *name:* A description of what this play does
. *hosts:* Which servers from your inventory to target
. *tasks:* A list of actions to perform

The basic structure looks like this:

[source,yaml]
----
---
- name: Play description
  hosts: target_hosts
  tasks:
    - name: Task description
      module_name:
        parameter: value
----

[IMPORTANT]
====
*Playbook Best Practices:*

* Start playbooks with `---` to indicate the beginning
* Always name your plays and tasks for readability
* Use 2 spaces for indentation consistently
* Use fully-qualified collection names (FQCN) for modules: `ansible.builtin.ping` instead of just `ping`
====

== Creating Your First Playbook

Let's start simple: we'll create a playbook that tests connectivity to your web servers using the `ping` module.

======
.☑️ Task 1 - Create a simple playbook
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

. Create a new file called `site.yml` in the `ansible-lab` folder
. Add the following content:
+
[source,yaml]
----
---
- name: Test connectivity to web servers
  hosts: webservers
  tasks:
    - name: Ping all web servers
      ansible.builtin.ping:
----

Let's break down what this playbook does:

* `---` marks the start of the YAML file
* `- name:` describes what this play does
* `hosts: webservers` targets the webservers group from your inventory
* `tasks:` begins the list of tasks to execute
* `ansible.builtin.ping:` uses the ping module to test connectivity
=====
======

======
.☑️ Task 2 - Validate and run your playbook
[%collapsible]
=====
NOTE: Switch to the *Terminal* tab

. First, validate the syntax:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml site.yml
----
+
This checks your YAML syntax without running anything.

. Now run the playbook:
+
[source,bash,role=execute]
----
ansible-playbook -i inventory.yml site.yml
----
+
You should see output showing successful pings to both web servers!
=====
======

== Understanding Modules and Parameters

Great! Your playbook works. Now let's understand how to do more with it.

=== What Are Modules?

Modules are the building blocks of Ansible automation. Each module performs a specific task:

* `ansible.builtin.ping` - Tests connectivity
* `ansible.builtin.package` - Installs/removes packages
* `ansible.builtin.service` - Manages services (start, stop, enable)
* `ansible.builtin.file` - Manages files and directories

=== Module Parameters

Most modules need parameters to know what to do. Parameters are written as key-value pairs under the module name:

[source,yaml]
----
ansible.builtin.debug:
  msg: "Hello World"   # The message to display
----

[source,yaml]
----
ansible.builtin.package:
  name: httpd          # Which package to install
  state: present       # present = installed, absent = removed
----

Different modules have different parameters. The `debug` module shows messages, the `package` module manages software, etc.

[TIP]
====
To see all parameters for any module, use:

[source,bash]
----
ansible-doc ansible.builtin.debug
ansible-doc ansible.builtin.package
----
====

== Building on Your Playbook

Now let's expand your playbook with multiple tasks and different module types to see how they work together.

======
.☑️ Task 3 - Add multiple tasks with different modules
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

Now let's expand your playbook with multiple tasks to show how different modules work. Update your `site.yml` file to match this:

[source,yaml]
----
---
- name: Configure web servers
  hosts: webservers
  tasks:
    - name: Ping all web servers
      ansible.builtin.ping:

    - name: Show server hostname
      ansible.builtin.debug:
        msg: "Running on {{ inventory_hostname }}"

    - name: Display welcome message
      ansible.builtin.debug:
        msg: "Welcome to the YAML Essentials lab!"
----

What changed?

* Kept the ping task to verify connectivity first
* Added a task using the `debug` module with a variable
* Added another debug task with a simple message
* Each task demonstrates different module parameters
=====
======

======
.☑️ Task 4 - Run the updated playbook
[%collapsible]
=====
NOTE: Switch to the *Terminal* tab

. First, validate the syntax:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml site.yml
----

. Run the playbook:
+
[source,bash,role=execute]
----
ansible-playbook -i inventory.yml site.yml
----
+
Watch as Ansible executes each task in order:

. ✅ Pings the web servers
. ✅ Shows the hostname for each server
. ✅ Displays the welcome message

You should see output showing each task executing successfully on both web servers. Notice how the hostname changes for each server - that's the `{{ inventory_hostname }}` variable in action!

[NOTE]
====
If any task fails, Ansible stops executing on that host. This prevents partial configurations that could cause problems.
====
