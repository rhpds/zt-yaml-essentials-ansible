= Common YAML Errors

== Introduction

Even experienced developers make YAML syntax errors. The good news? YAML errors follow predictable patterns, and learning to recognize them will save you hours of debugging time.

In this module, you will:

* Identify and fix common YAML syntax errors
* Understand indentation problems
* Recognize tab vs. space issues
* Debug case sensitivity mistakes
* Fix quote-related errors
* Catch missing colons

[NOTE]
====
For this module, we've pre-loaded five broken YAML files (`broken1.yml` through `broken5.yml`) in your `ansible-lab` folder. Each file contains a different type of common error for you to identify and fix.
====

== Hands-On Experience

======
.☑️ Task 1 - Fix indentation problems
[%collapsible]
=====
The file `broken1.yml` has intentional indentation errors. Let's find and fix them.

Here's what's in the file:

[source,yaml]
----
---
- name: Broken indentation example
  hosts: webservers
  tasks:
  - name: This task is not properly indented
    ansible.builtin.ping:
   - name: This task has wrong indentation
     ansible.builtin.debug:
       msg: "Wrong indent"
----

. Switch to *Terminal* tab and check the syntax:
+
[source,bash,role=execute]
----
yamllint broken1.yml
----

. Switch to *VSCode Editor* and fix with correct indentation:
+
[source,yaml]
----
---
- name: Fixed indentation example
  hosts: webservers
  tasks:
    - name: This task is properly indented
      ansible.builtin.ping:

    - name: This task also has correct indentation
      ansible.builtin.debug:
        msg: "Correct indent"
----
+

. Switch to *Terminal* and verify:
+
[source,bash,role=execute]
----
yamllint broken1.yml
----

.☑️ Task 3 - Fix case sensitivity issues
[%collapsible]
=====
The file `broken3.yml` has a case sensitivity error. The variable is defined as `http_port` but referenced as `HTTP_PORT`.

Here's what's in the file:

[source,yaml]
----
---
- name: Case sensitivity problem
  hosts: webservers
  vars:
    http_port: 80
  tasks:
    - name: Use the port variable
      ansible.builtin.debug:
        msg: "Port is {{ HTTP_PORT }}"
----

. Switch to *Terminal* tab and run with verbose mode:
+
[source,bash,role=execute]
----
ansible-playbook -i inventory.yml broken3.yml -v
----

. Switch to *VSCode Editor* and fix with consistent casing:
+
[source,yaml]
----
---
- name: Case sensitivity fixed
  hosts: webservers
  vars:
    http_port: 80
  tasks:
    - name: Use the port variable
      ansible.builtin.debug:
        msg: "Port is {{ http_port }}"
----
+

. Switch to *Terminal* and verify:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken3.yml
----

.☑️ Task 4 - Fix missing or incorrect quotes
[%collapsible]
=====
The file `broken4.yml` has a variable reference without quotes. Jinja2 variables must be quoted when they start a value.

Here's what's in the file:

[source,yaml]
----
---
- name: Quote problems
  hosts: webservers
  vars:
    package_name: httpd
  tasks:
    - name: Install package without quotes
      ansible.builtin.package:
        name: {{ package_name }}
        state: present
----

. Switch to *Terminal* tab and check syntax:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken4.yml
----

. Switch to *VSCode Editor* and fix with proper quotes:
+
[source,yaml]
----
---
- name: Quote problems fixed
  hosts: webservers
  vars:
    package_name: httpd
  tasks:
    - name: Install package with quotes
      ansible.builtin.package:
        name: "{{ package_name }}"
        state: present
----
+

. Switch to *Terminal* and verify:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken4.yml
----

.☑️ Task 5 - Fix missing colons
[%collapsible]
=====
The file `broken5.yml` is missing a colon after `tasks`. In YAML, all dictionary keys must have a colon.

Here's what's in the file:

[source,yaml]
----
---
- name: Missing colon
  hosts: webservers
  tasks

      ansible.builtin.ping:
----

. Switch to *Terminal* tab and check syntax:
+
[source,bash,role=execute]
----
yamllint broken5.yml
----

. Switch to *VSCode Editor* and fix by adding the colon:
+
[source,yaml]
----
---
- name: Missing colon fixed
  hosts: webservers
  tasks:
    - name: Ping hosts
      ansible.builtin.ping:
----
+

. Switch to *Terminal* and verify:
+
[source,bash,role=execute]
----
yamllint broken5.yml
----

== Key Takeaways

In this module, you learned:

* ✅ Use *2 spaces* for indentation, never tabs
* ✅ YAML is *case-sensitive* - match variable names exactly
* ✅ Quote variables at the start of values: `"{{ var }}"`
* ✅ Every dictionary key needs a colon: `key:`
* ✅ Use `yamllint` to catch YAML syntax errors
* ✅ Common errors follow predictable patterns
* ✅ Read error messages carefully - they point to the problem
