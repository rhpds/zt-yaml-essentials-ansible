= Common YAML Errors

== Introduction

Even experienced developers make YAML syntax errors. The good news? YAML errors follow predictable patterns, and learning to recognize them will save you hours of debugging time.

In this module, you will:

* Identify and fix common YAML syntax errors
* Understand indentation problems
* Recognize tab vs. space issues
* Debug case sensitivity mistakes
* Fix quote-related errors
* Catch missing colons

== Hands-On Experience

======
.☑️ Task 1 - Fix indentation problems
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

Indentation errors are the #1 cause of YAML failures. Remember: YAML requires *exactly 2 spaces* per level.

. In the left sidebar, hover over the `ansible-lab` folder
. Click the *New File* icon (page with a plus sign)
. Type `broken1.yml` as the filename and press Enter
. In the editor, add the following content with intentional indentation errors:
+
[source,yaml]
----
---
- name: Broken indentation example
  hosts: webservers
  tasks:
  - name: This task is not properly indented
    ansible.builtin.ping:
   - name: This task has wrong indentation
     ansible.builtin.debug:
       msg: "Wrong indent"
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and try to check the syntax:
+
[source,bash,role=execute]
----
yamllint broken1.yml
----
+
You'll see errors about indentation!

. Now fix the file with correct indentation in VSCode. Replace all the content with:
+
[source,yaml]
----
---
- name: Fixed indentation example
  hosts: webservers
  tasks:
    - name: This task is properly indented
      ansible.builtin.ping:

    - name: This task also has correct indentation
      ansible.builtin.debug:
        msg: "Correct indent"
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and verify the fix:
+
[source,bash,role=execute]
----
yamllint broken1.yml
----

WARNING: *Indentation Rules:* Use exactly 2 spaces per indentation level. Never mix spaces and tabs. Every child element must be indented from its parent. All items at the same level must have the same indentation.

.☑️ Task 2 - Detect tabs instead of spaces
[%collapsible]
=====
NOTE: Switch to the *Terminal* tab

YAML does not allow tab characters. Many editors insert tabs when you press the Tab key, causing hard-to-see errors.

. Create a file with tab characters using the terminal:
+
[source,bash,role=execute]
----
printf "---\n- name: Broken tabs example\n  hosts: webservers\n  tasks:\n\t- name: Task with tab\n\t  ansible.builtin.ping:\n" > broken2.yml
----

. Try to validate it:
+
[source,bash,role=execute]
----
yamllint broken2.yml
----
+
You'll see: `found character '\t' that cannot start any token`

. Check for tabs in the file:
+
[source,bash,role=execute]
----
cat -A broken2.yml | grep "^I"
----
+
The `^I` shows where tab characters are.

. Switch to the *VSCode Editor* tab and fix the file. Open `broken2.yml` and replace all the content with:
+
[source,yaml]
----
---
- name: Fixed tabs example
  hosts: webservers
  tasks:
    - name: Task with spaces only
      ansible.builtin.ping:
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and verify the fix:
+
[source,bash,role=execute]
----
yamllint broken2.yml
----

TIP: *Configure Your Editor:* Set your text editor to convert tabs to spaces, set tab width to 2 spaces, show whitespace characters (helps spot tabs), and auto-indent with spaces. Most modern editors (VS Code, vim, nano) can do this.

.☑️ Task 3 - Fix case sensitivity issues
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

Variable names and keys are case-sensitive in YAML. `HTTP_PORT` and `http_port` are different variables.

. Create a new file called `broken3.yml`:
+
* Click the *New File* icon in the left sidebar
* Name it `broken3.yml`
* Add the following content:
+
[source,yaml]
----
---
- name: Case sensitivity problem
  hosts: webservers
  vars:
    http_port: 80
  tasks:
    - name: Use the port variable
      ansible.builtin.debug:
        msg: "Port is {{ HTTP_PORT }}"
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and check for undefined variables:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken3.yml
----
+
The syntax check passes, but the variable won't be found at runtime!

. Run it with verbose mode to see the variable error:
+
[source,bash,role=execute]
----
ansible-playbook -i inventory.yml broken3.yml -v
----
+
You'll see the undefined variable `HTTP_PORT` in the output.

. Switch to the *VSCode Editor* tab and fix the file with consistent casing. Replace all the content with:
+
[source,yaml]
----
---
- name: Case sensitivity fixed
  hosts: webservers
  vars:
    http_port: 80
  tasks:
    - name: Use the port variable
      ansible.builtin.debug:
        msg: "Port is {{ http_port }}"
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and verify it works:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken3.yml
----

IMPORTANT: *Case Sensitivity Checklist:* Variable names must match exactly - `http_port` defined, `http_port` used (not `HTTP_PORT`). Module names are always lowercase: `ansible.builtin.ping`. Dictionary keys must match exactly between definition and use.

.☑️ Task 4 - Fix missing or incorrect quotes
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

Variables in YAML values must be quoted if they start the value, but quoting rules can be tricky.

. Create a new file called `broken4.yml`:
+
* Click the *New File* icon in the left sidebar
* Name it `broken4.yml`
* Add the following content:
+
[source,yaml]
----
---
- name: Quote problems
  hosts: webservers
  vars:
    package_name: httpd
  tasks:
    - name: Install package without quotes
      ansible.builtin.package:
        name: {{ package_name }}
        state: present
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and try to check syntax:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken4.yml
----
+
You'll see: `found undefined alias` or similar error.

. Switch to the *VSCode Editor* tab and fix the file with proper quotes. Replace all the content with:
+
[source,yaml]
----
---
- name: Quote problems fixed
  hosts: webservers
  vars:
    package_name: httpd
  tasks:
    - name: Install package with quotes
      ansible.builtin.package:
        name: "{{ package_name }}"
        state: present
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and verify the fix:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken4.yml
----

NOTE: *Quoting Rules for Variables:* Variables at the START of a value need quotes: `name: "{{ package_name }}"` is correct. Variables NOT at the start don't need quotes (but can have them): `msg: "Installing {{ package_name }}"` is correct. NEVER without quotes when at start: `name: {{ package_name }}` will cause an error!

.☑️ Task 5 - Fix missing colons
[%collapsible]
=====
NOTE: In the *VSCode Editor* tab

YAML dictionaries require a colon (`:`) after each key. Forgetting the colon is a common typo.

. Create a new file called `broken5.yml`:
+
* Click the *New File* icon in the left sidebar
* Name it `broken5.yml`
* Add the following content:
+
[source,yaml]
----
---
- name: Missing colon
  hosts: webservers
  tasks
    - name: Ping hosts
      ansible.builtin.ping:
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and check syntax:
+
[source,bash,role=execute]
----
yamllint broken5.yml
----
+
You'll see: `could not find expected ':'`

. Switch to the *VSCode Editor* tab and fix the file by adding the colon. Replace all the content with:
+
[source,yaml]
----
---
- name: Missing colon fixed
  hosts: webservers
  tasks:
    - name: Ping hosts
      ansible.builtin.ping:
----
+
IMPORTANT: Save the file.

. Switch to the *Terminal* tab and verify:
+
[source,bash,role=execute]
----
yamllint broken5.yml
----

== Key Takeaways

In this module, you learned:

* ✅ Use *2 spaces* for indentation, never tabs
* ✅ YAML is *case-sensitive* - match variable names exactly
* ✅ Quote variables at the start of values: `"{{ var }}"`
* ✅ Every dictionary key needs a colon: `key:`
* ✅ Use `yamllint` to catch YAML syntax errors
* ✅ Common errors follow predictable patterns
* ✅ Read error messages carefully - they point to the problem
