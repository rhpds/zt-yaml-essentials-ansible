= 4. Common YAML Errors

== Introduction

Even experienced developers make YAML syntax errors. The good news? YAML errors follow predictable patterns, and learning to recognize them will save you hours of debugging time.

In this module, you will:

* Identify and fix common YAML syntax errors
* Understand indentation problems
* Debug case sensitivity mistakes
* Fix quote-related errors
* Catch missing colons

[NOTE]
====
For this module, we've pre-loaded four broken YAML files (`broken1.yml` through `broken4.yml`) in your `ansible-lab` folder. Each file contains a different type of common error for you to identify and fix.
====

== Hands-On Experience

======
.☑️ Task 1 - Fix indentation problems
[%collapsible]
=====
The file `broken1.yml` has intentional indentation errors. Let's find and fix them.

. Switch to *VSCode Editor* tab and open `broken1.yml` to see what's wrong

. Switch to *Terminal* tab and check the syntax:
+
[source,bash,role=execute]
----
yamllint broken1.yml
----
+
Notice the indentation errors in the output.

. Switch to *VSCode Editor* and fix the indentation. The corrected version should look like this:
+
[source,yaml]
----
---
- name: Fixed indentation example
  hosts: webservers
  tasks:
    - name: This task is properly indented
      ansible.builtin.ping:

    - name: This task also has correct indentation
      ansible.builtin.debug:
        msg: "Correct indent"
----
+

. Switch to *Terminal* and verify:
+
[source,bash,role=execute]
----
yamllint broken1.yml
----

.☑️ Task 2 - Fix case sensitivity issues
[%collapsible]
=====
The file `broken2.yml` has a case sensitivity error. A variable is defined with one case but referenced with different casing.

. Switch to *VSCode Editor* tab and open `broken2.yml` to inspect it

. Switch to *Terminal* tab and run with verbose mode:
+
[source,bash,role=execute]
----
ansible-playbook -i inventory.yml broken2.yml -v
----

. Switch to *VSCode Editor* and fix the variable name to use consistent casing. The corrected version should look like this:
+
[source,yaml]
----
---
- name: Case sensitivity fixed
  hosts: webservers
  vars:
    http_port: 80
  tasks:
    - name: Use the port variable
      ansible.builtin.debug:
        msg: "Port is {{ http_port }}"
----
+

. Switch to *Terminal* and verify:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken2.yml
----
=====

.☑️ Task 3 - Fix missing or incorrect quotes
[%collapsible]
=====
The file `broken3.yml` has a variable reference without quotes. Remember: Jinja2 variables must be quoted when they start a value.

. Switch to *VSCode Editor* tab and open `broken3.yml` to inspect it

. Switch to *Terminal* tab and check syntax:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken3.yml
----

. Switch to *VSCode Editor* and add quotes around the variable. The corrected version should look like this:
+
[source,yaml]
----
---
- name: Quote problems fixed
  hosts: webservers
  vars:
    package_name: httpd
  tasks:
    - name: Install package with quotes
      ansible.builtin.package:
        name: "{{ package_name }}"
        state: present
----
+

. Switch to *Terminal* and verify:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml broken3.yml
----
=====

.☑️ Task 4 - Fix missing colons
[%collapsible]
=====
The file `broken4.yml` is missing a colon somewhere. Remember: In YAML, all dictionary keys must have a colon.

. Switch to *VSCode Editor* tab and open `broken4.yml` to inspect it

. Switch to *Terminal* tab and check syntax:
+
[source,bash,role=execute]
----
yamllint broken4.yml
----

. Switch to *VSCode Editor* and add the missing colon. The corrected version should look like this:
+
[source,yaml]
----
---
- name: Missing colon fixed
  hosts: webservers
  tasks:
    - name: Ping hosts
      ansible.builtin.ping:
----
+

. Switch to *Terminal* and verify:
+
[source,bash,role=execute]
----
yamllint broken4.yml
----
