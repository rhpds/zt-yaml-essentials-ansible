== Debugging Tools

You've been using `yamllint` throughout this lab. Now let's explore its full capabilities and learn how to use it alongside other debugging tools.

=== Tool 1: yamllint - Advanced Usage

You've already used `yamllint` for basic syntax checking. Here are more advanced features:

*Basic usage (you've done this):*
[source,bash]
----
yamllint inventory.yml
yamllint site.yml
----

*Show specific error types with parsable format:*
[source,bash]
----
yamllint -f parsable site.yml
----

*Check multiple files at once:*
[source,bash]
----
yamllint *.yml
----

[TIP]
====
*Understanding yamllint Error Categories:*

* `syntax error` - Invalid YAML that won't parse (MUST FIX)
* `indentation` - Wrong number of spaces (MUST FIX)
* `trailing-spaces` - Spaces at end of lines (cosmetic, safe to ignore)
* `line-length` - Lines too long (cosmetic, safe to ignore)
* `document-start` - Missing `---` (cosmetic, but best practice to include)
====

=== Tool 2: ansible-playbook --syntax-check

This checks Ansible-specific syntax beyond basic YAML.

*Usage:*
[source,bash]
----
ansible-playbook --syntax-check -i inventory.yml site.yml
----

*What it catches:*

* Undefined variables (sometimes)
* Invalid module names
* Missing required parameters
* Incorrect play structure

[NOTE]
====
`--syntax-check` only validates syntax, it doesn't run the playbook or check if the logic is correct.
====

=== Tool 3: ansible-playbook --check

Check mode (dry-run) shows what would happen without making changes.

*Usage:*
[source,bash]
----
ansible-playbook --check -i inventory.yml site.yml
----

*What it reveals:*

* Undefined variables that only appear at runtime
* Connection issues
* Missing inventory hosts
* Permission problems

[WARNING]
====
*Check Mode Limitations:*

Check mode *simulates* changes without making them, which can cause issues:

* ✅ Works: ping, debug, fact gathering
* ❌ Fails: service tasks when packages aren't installed yet

For playbooks with service tasks (like this lab's examples), use `--syntax-check` for validation instead.
====

== Troubleshooting Workflow

When you encounter a YAML error, follow this process:

[arabic]
. *Read the error message carefully* - It usually tells you the line number and what's wrong
. *Check indentation* - Count spaces, ensure consistency
. *Look for tabs* - Use `cat -A filename.yml` to reveal tabs
. *Verify quotes* - Variables at the start of values need quotes
. *Check colons* - Every dictionary key needs a `:` after it
. *Validate casing* - Variable and key names must match exactly
. *Run yamllint* - Catches pure YAML syntax issues
. *Run --syntax-check* - Catches Ansible-specific issues
. *Test the playbook* - For this lab, use `--syntax-check` for validation

== 🏆 Final Challenge: Debug the Broken Playbook

You've learned about YAML syntax, playbook structure, variables, and common errors. Now it's time to prove you can debug a real-world broken playbook!

In the previous modules, you fixed isolated errors one at a time. But real-world debugging isn't that clean - you often encounter multiple errors in the same file. This final challenge simulates that experience.

======
.☑️ Task 2 - Final Debugging Challenge
[%collapsible]
=====
The file `debug-challenge.yml` is a broken playbook that contains **MULTIPLE** errors - all the types you've learned in this lab:

* Missing document start (`---`)
* Indentation errors
* Tab characters
* Case sensitivity issues
* Missing quotes
* Missing colons
* Structural problems

Your mission: Find and fix ALL the errors to get the playbook running successfully.

. Switch to *VSCode Editor* tab and open `debug-challenge.yml` to inspect it

. Switch to *Terminal* tab and start debugging with `yamllint`:
+
[source,bash,role=execute]
----
yamllint debug-challenge.yml
----
+
Fix the YAML syntax errors first.

. Run Ansible syntax check:
+
[source,bash,role=execute]
----
ansible-playbook --syntax-check -i inventory.yml debug-challenge.yml
----
+
This will catch additional Ansible-specific issues.

. Keep iterating between VSCode and the Terminal, fixing errors until both tools report success

. Once all errors are fixed, run the playbook for real:
+
[source,bash,role=execute]
----
ansible-playbook -i inventory.yml debug-challenge.yml
----
+
If it runs successfully, congratulations! You've debugged a complex broken playbook! 🎉

[TIP]
====
**Debugging Strategy:**

1. Start with `yamllint` - fix basic YAML errors first
2. Use `--syntax-check` - catch Ansible-specific issues
3. Read error messages carefully - they tell you the line number
4. Fix one error at a time and re-validate
5. Count your spaces - indentation must be exact
====

== Common Error Messages

[cols="2,3",options="header"]
|===
|Error Message |Solution

|`found character '\t' that cannot start any token`
|Remove tabs, use spaces only

|`could not find expected ':'`
|Add colon after dictionary key

|`mapping values are not allowed here`
|Check indentation, often caused by wrong spacing

|`found undefined alias`
|Add quotes around variables: `"{{ var }}"`

|`ERROR! Syntax Error while loading YAML`
|Run yamllint to find the specific issue

|`ERROR! The field 'hosts' is required`
|Add the `hosts:` line to your play

|`'item' is undefined`
|Add `loop:` when using `{{ item }}`
|===

== Key Takeaways

Congratulations on completing YAML Essentials for Ansible! Here's everything you've mastered:

**YAML Fundamentals:**
* ✅ YAML uses `.yml` extension and starts with `---`
* ✅ YAML is case-sensitive - maintain consistent casing
* ✅ Use 2 spaces for indentation (never tabs!)
* ✅ Scalars, lists, and dictionaries are the building blocks
* ✅ Nested structures require consistent indentation

**Ansible Playbooks:**
* ✅ Playbooks contain plays that target specific hosts
* ✅ Tasks execute in order from top to bottom
* ✅ Modules are the building blocks that perform actual work
* ✅ Use `become: true` for privilege escalation
* ✅ Use FQCN (Fully Qualified Collection Names)

**Variables & Best Practices:**
* ✅ Define variables in `vars:` section as key-value pairs
* ✅ Reference variables with `"{{ variable_name }}"` syntax
* ✅ Use `loop:` to iterate over list variables
* ✅ Follow naming conventions: lowercase with underscores
* ✅ Document why, not what, in comments

**Debugging & Troubleshooting:**
* ✅ Use `yamllint` to catch YAML syntax errors
* ✅ Use `--syntax-check` for Ansible-specific validation
* ✅ Follow a systematic troubleshooting workflow
* ✅ Read error messages carefully - they point to the problem
* ✅ **Debug complex playbooks with multiple errors** - you did it!
